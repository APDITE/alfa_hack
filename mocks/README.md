# mocks

Локальные моки внешних источников: ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес» и бюро кредитных историй. Отдают синтетические данные, к реальным системам доступа нет. Тот же файл `data/companies.json` служит сидом компаний для бэкенда, поэтому ИНН везде совпадают.

## Запуск

```bash
uv sync                                   # зависимости по uv.lock, Python 3.12
uv run uvicorn app.main:app --port 8000   # сервис
uv run pytest                             # тесты
uv run python generate.py                 # пересобрать data/companies.json
```

В compose сервис называется `mocks`, бэкенд ходит на `http://mocks:8000`. Swagger: `/docs`, проверка живости: `GET /health`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MOCKS_DATA_PATH` | `data/companies.json` | путь к файлу с компаниями |
| `MOCKS_SYNTHETIC_UNKNOWN_INN` | `1` | `0` отключает синтетику для неизвестных ИНН (тогда они дают 404) |

## Контракт

Все три источника отвечают `200` или `404` (компании нет в источнике).

Неизвестный ИНН из 10 цифр (ООО) или 12 цифр (ИП) получает синтетику, детерминированную от ИНН (сценарий 12, своя компания жюри): ЕГРЮЛ и БКИ отвечают `200`, а «Прозрачный бизнес» `404`, поэтому финпоказатели клиент вводит сам. Кредитная история безобидная: просрочек 30+ дней нет, исход зависит от введённых цифр. ИНН другого формата дают `404`. Выключенный источник отвечает `503`, даже если ИНН неизвестен.

- `GET /mock/egrul/{inn}`: `inn, name, legal_form (OOO|IP), okved, registration_date, region, status (active|liquidating|liquidated), director`
- `GET /mock/transparent-business/{inn}`: `inn, revenue_year, expenses_year, liabilities_total, employees, tax_arrears`
- `GET /mock/bki/{inn}`: `inn, active_loans, overdue_count, max_overdue_days, total_debt`
- `POST /mock/admin/availability` с телом `{"service": "egrul" | "transparent_business" | "bki", "available": false}` включает и выключает источник. Текущее состояние: `GET /mock/admin/availability`.

Состояние доступности хранится в памяти процесса: это переключатель для демонстрации, перезапуск контейнера включает все источники обратно.

## Данные

`generate.py` с фиксированным seed пишет один файл: 8 демо-компаний и 180 фоновых. Два запуска дают побайтово одинаковый результат, тест сверяет закоммиченный файл с генератором. Формат записи: поля ЕГРЮЛ плюс `financials` и `credit_history` (`null`, если источник компанию не знает) и `demo` (`null` у фоновых).

Закономерности в фоновых данных заданы вручную: чем ниже выдуманное "качество" компании, тем меньше рентабельность, больше долги, чаще просрочки и налоговая задолженность. Реальных меток дефолта нет, это ограничение.

У ИП в фоне ИНН из 12 цифр, у ООО из 10, контрольные суммы не считаются. Демо-ИНН не проходят проверку контрольной суммы (и у двух демо-ИП они 10-значные), поэтому бэкенд её требовать не должен.

Реквизиты демо-компаний (название, дата регистрации, регион, директор) совпадают с `backend/config/demo_companies.yaml`, номера сценариев с `docs/scenarios.md`. Тест `test_demo_registry_matches_backend_seed` ловит расхождение.

### Демо-компании

Оценка показана для заявки из поля `demo.suggested_applications` (скоринг `scorecard-0.1.0`). Исход считают кредитные правила бэкенда по порогам из `backend/config/products.yaml`.

| ИНН | Сценарий | Заявка | PD | Класс | Исход |
|---|---|---|---|---|---|
| 7700000001 | 1 и 7. Сильная компания | оборотный, 1.5 млн, 12 мес | 0.017 | low | автоодобрение; в сценарии 7 перед заявкой выключить БКИ |
| 7700000002 | 2. Высокая нагрузка при хорошем риске | оборотный, 4 млн, 6 мес | 0.080 | low | другие условия: срок или сумма |
| 7700000003 | 3. Неполные данные | оборотный, 0.8 млн, 12 мес | нет | нет | «Прозрачный бизнес» отвечает 404, запрос уточнения |
| 7700000004 | 4. Просрочка 120 дн. | оборотный, 3 млн, 12 мес | 0.762 | high | отказ |
| 7700000005 | 5. Низкая рентабельность, 3 кредита | оборотный, 2 млн, 12 мес | 0.147 | medium | серая зона, ручная проверка |
| 7700000006 | 6. Ликвидация | оборотный, 2 млн, 12 мес | 0.022 | low | отказ по статусу `liquidating` |
| 7700000007 | 8. Один скоринг, два продукта | 2 млн, 24 мес | 0.106 | medium | оборотный: автоодобрение, оборудование: ручная проверка |
| 7700000008 | 11. Бизнесу 8 месяцев | оборудование, 2 млн, 24 мес | 0.057 | low | другие условия: оборотный кредит |

Сценарий 1 по договору ориентировался на PD около 0.05, у нас 0.017: данные сильной компании заданы договором, а шкала подобрана так, чтобы сошлись остальные ориентиры. Исход одинаковый.

Для сценария 7:

```bash
curl -X POST localhost:8000/mock/admin/availability -H "content-type: application/json" \
     -d '{"service": "bki", "available": false}'
# отправить заявку компании 7700000001, затем вернуть источник
curl -X POST localhost:8000/mock/admin/availability -H "content-type: application/json" \
     -d '{"service": "bki", "available": true}'
```

## Зависимости (для THIRD_PARTY_NOTICES)

fastapi, uvicorn, pydantic, pytest и httpx (только тесты). Образы: `python:3.12-slim-bookworm`, `ghcr.io/astral-sh/uv:0.13.4`. Все данные синтетические, интеграции ЕГРЮЛ/ЕГРИП, «Прозрачный бизнес» и БКИ смоделированы.
